The claim, in numbers

Most browsers tell you what they collect. This one can tell you what it doesn't.

2

0

Ads and trackers blocked by default

EasyList and EasyPrivacy are compiled into the app when it is built. Vela never fetches a filter list while running, because that would be a third kind of request — the lists refresh by shipping a new version.

Private windows that really are

Ctrl Shift N opens a session held only in memory. A test in the repository browses inside one and proves nothing reached the disk.

One user agent for everyone

No per-install randomisation. A string unique to your copy is a fingerprint, not a defence — every Vela says exactly the same thing.

Telemetry caught while it is written

In development an assertion on the session's own network layer logs any request that is not one of the two above, so an accidental call home shows up during the build rather than after it ships.

The assistant

It runs inside Vela, so there is no request to make

The sidebar assistant defaults to a model running in Vela itself. Nothing else to install, no second program, and no port to talk to: llama.cpp is linked into the process, so a question never becomes a network request in the first place. That is a stronger claim than “it only goes to localhost” — there is no request.

Vela ships without a model on purpose. Four gigabytes inside the installer would be a miserable download for everyone who never opens the panel, so Settings offers a short catalogue instead, and the one you pick downloads once — resumable, and checked against its SHA-256 before it is ever used.

Ollama is still there for anyone already running it, and a hosted service works with a key you paste in. Only that last one adds a network destination, which is exactly why it is not the default.

The Opera parts

A browser you would want to use anyway

Privacy that costs you the features you already rely on is a trade most people quite reasonably refuse. Vela does not ask for it.

Workspaces on a left rail

Named tab groups, the way Opera does them. Leaving a workspace suspends its tabs — an idle one costs storage for its titles and nothing else, because the renderer is genuinely handed back.

Web panels beside the page

Dock any site into the sidebar. Each panel is an ordinary view on the same hardened session a tab uses — same sandbox, same blocking, no preload — and closing it destroys the view rather than leaving a renderer running.

Speed Dial, bookmarks, history

A new tab page with favicons cached on your own disk, a bookmarks bar, and local history that feeds the command palette. Per-site zoom that sticks, on Ctrl + and Ctrl 0.

Bang shortcuts, resolved here

!gh, !yt and !w expand on your machine, so the address reaches the site without a search engine seeing the query on the way past.

Downloads that survive a bad line

A bubble rises over the page as a file lands, with a rate and a time remaining. Large transfers retry with a widening wait and resume from the part file rather than starting over.

A menu that knows what you clicked

Save a link, image, video or audio file, copy an address, open it in a new tab, or search a selection with the engine you chose on the first run. Native, so it floats above the page instead of being painted underneath it.

Two refusals

Things a privacy browser is expected to ship, and this one will not

No built-in VPN

A browser-branded “free VPN” is somebody else's server watching all your traffic — the exact arrangement this browser exists to avoid, and it needs infrastructure Vela does not run.

Settings takes a proxy or VPN you already trust instead, and routes every session through it.

No hosted account, and no sync

Vela has a sign-in, but it unlocks an encrypted file on your own computer. The master password is never stored — only a separate scrypt derivation of it — and saved credentials are AES-256-GCM under a key derived the same way. There is no password reset, because there is nobody to ask.

Sign in to a site once and Vela offers to remember it, then fills it as the page loads. The password it captures never reaches the part of Vela that draws the prompt.

Installing

The first launch will warn you. Here is why, and what to click.

Vela's builds are not code-signed yet, so your operating system will say it does not recognise them. Nothing is wrong with the download; the certificate that would quiet the warning is a running cost a free program does not have.

Windows

SmartScreen says “Windows protected your PC”. Click More info, then Run anyway.

An .exe installer, for x64 and ARM64.

macOS

Gatekeeper says Vela “cannot be opened”. Right-click the app, choose Open, then confirm — or run xattr -dr com.apple.quarantine /Applications/Vela.app.

One universal .dmg: Apple Silicon and Intel in the same file.

Linux

Make it executable first — chmod +x Vela-*.AppImage — then run it. No install step, and no root.

An .AppImage, for x86_64 and ARM64.

Every platform is built on a machine of its own kind. A .dmg can only be produced on macOS and an .AppImage on Linux, and neither cross-compiles from a Windows desktop — which is why 0.1.0 shipped Windows-only, and 0.1.1 is the first release carrying all three.

Two requests. One file. No account.

Free and open source. Nothing to sign up for, and nothing to switch off once it is installed.
